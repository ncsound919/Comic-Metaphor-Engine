# Comic Book Metaphor Engine - Marathon Build Specification
## Cheetah v3 Pro Benchmarking Project

**Project Goal**: Build a complete comic book metaphor engine that maps storylines to real-world applications (podcasts, marketing, dialogue) with full Cheetah v3 benchmarking integration.

**Benchmark Objective**: Test Cheetah v3's ability to build a complex, multi-phase system with data ingestion, AI-driven mapping, narrative generation, and quality scoring—all instrumented for performance analysis.

## TEMPLATE_01: ingest.py

**Purpose**: Parse existing files into structured KnowledgeBase
- Parse `Storylines for metaphor engine` (text file with 4 protocols)
- Parse `IHS_*.csv` files for TAP metrics and scoring frameworks
- Convert to JSONL in `processed/` directory
- Create embeddings for semantic search

**Key Functions**:
- `parse_storylines_file(path: str) -> List[Protocol]`
- `parse_ihs_csv(path: str) -> Dict[str, Any]`
- `build_knowledge_base(raw_dir: str) -> KnowledgeBase`
- `generate_embeddings(texts: List[str]) -> np.ndarray`
- `save_processed_data(kb: KnowledgeBase, output_dir: str)`

**Data Sources**:
- `Storylines for metaphor engine` → Protocol objects (Armor Wars, Secret Invasion, Days of Future Past, Planet Hulk)
- `IHS_Unified_Flow.csv` → TAP metric definitions
- `IHS_System_Foundations.json` → System configuration
- `IHS_Execution_Tools.json` → Format templates

**Output**: 
- `processed/protocols.jsonl`
- `processed/universes.jsonl`
- `processed/knowledge_base.json`
- `processed/embeddings.npy`

**Dependencies**: pandas, numpy, json, pathlib

## TEMPLATE_02: index.py

**Purpose**: Semantic search and retrieval over protocols/arcs
- FAISS vector index for similarity search
- Filter-based retrieval (risk_category, tone, format)
- Cache-friendly lookups

**Key Classes**:
- `MetaphorIndex`: Main search interface
  - `search_protocols(query: str, filters: Dict, top_k: int) -> List[Protocol]`
  - `search_by_risk_category(category: RiskCategory) -> List[Protocol]`
  - `search_by_theme(theme: str, top_k: int) -> List[Protocol]`
  - `get_protocol_by_id(id: str) -> Optional[Protocol]`

**Key Functions**:
- `build_index(kb: KnowledgeBase) -> MetaphorIndex`
- `compute_query_embedding(query: str) -> np.ndarray`
- `filter_protocols(protocols: List[Protocol], filters: Dict) -> List[Protocol]`

**Cache Integration**: Deterministic cache keys based on query+filters hash

**Dependencies**: faiss-cpu (or faiss-gpu), numpy, sklearn

## TEMPLATE_03: metaphor_engine.py

**Purpose**: Core mapping logic from topic → comic metaphor
- Analyze user topic to extract domain, tension, emotion
- Match to narrative patterns (hero's journey, redemption arc, etc.)
- Select best protocol/arc via index search
- Build MetaphorMapping with element-by-element translations

**Key Classes**:
- `MetaphorEngine`:
  - `generate_mapping(topic: str, format: FormatType, tone: ToneType, constraints: Dict) -> MetaphorMapping`
  - `analyze_topic(topic: str) -> Dict[str, Any]`
  - `select_protocol(analysis: Dict, index: MetaphorIndex) -> Protocol`
  - `build_mapping(protocol: Protocol, topic_analysis: Dict) -> MetaphorMapping`
  - `score_mapping(mapping: MetaphorMapping) -> Dict[str, float]`

**Integration**:
- Uses `codex_adapter` to score mappings
- Uses `index` for protocol retrieval
- Produces cache-keyed results

**Dependencies**: index.py, codex_adapter.py, schema.py

---

## TEMPLATE_04: narrative_generator.py

**Purpose**: Generate outlines and full scripts from mappings
- Format-specific templates (podcast, marketing email, dialogue)
- Beat-by-beat outline generation
- Full narrative drafting
- Word count management

**Key Classes**:
- `NarrativeGenerator`:
  - `generate_outline(context: GenerationContext) -> NarrativeOutline`
  - `generate_script(outline: NarrativeOutline, context: GenerationContext) -> NarrativeOutput`
  - `_build_podcast_outline(context: GenerationContext) -> NarrativeOutline`
  - `_build_marketing_outline(context: GenerationContext) -> NarrativeOutline`
  - `_build_dialogue_outline(context: GenerationContext) -> NarrativeOutline`

**Templates**:
- Podcast monologue: Hook → 3-5 beats → conclusion
- Marketing email: Subject → pain point → solution (metaphor) → CTA
- Dialogue script: Setup → conflict → resolution beats

**Dependencies**: schema.py, string templates

## TEMPLATE_06: codex_adapter.py

**Purpose**: Integrate `codex_engine.py` for quality scoring
- Wrap `compute_report()` function from existing codex_engine
- Map MetaphorMapping fields to codex inputs (Trueness, Flow, PCS, etc.)
- Extract scores and return as structured data

**Key Functions**:
- `score_mapping(mapping: MetaphorMapping, protocol: Protocol) -> Dict[str, float]`
- `build_codex_input(mapping: MetaphorMapping) -> Dict[str, Any]`
- `parse_codex_output(report_md: str, audit: Dict) -> Dict[str, float]`

**Codex Metrics**:
- Trueness: Signal-to-baggage ratio (mapping clarity)
- Tap10: Weighted effectiveness
- Flow: Readiness × inverse drag × resources
- PCS: Partner/protocol fit
- RPS: Rollout priority after risk
- CU: Deliverable capacity

**Dependencies**: ../codex_engine.py, schema.py

---

## TEMPLATE_07: tools_interface.py

**Purpose**: Cheetah v3 tool wrappers for benchmarking
- Register all engine functions as Cheetah-compatible tools
- Add instrumentation for cache, resource monitoring
- Ensure deterministic cache keys

**Tools to Expose**:
1. `comic_corpus.search_protocols(query, filters, top_k)` → List[Protocol]
2. `comic_metaphor.generate_mapping(topic, format, tone, constraints)` → MetaphorMapping
3. `comic_metaphor.generate_outline(mapping_id)` → NarrativeOutline
4. `comic_metaphor.generate_script(outline_id, context)` → NarrativeOutput
5. `comic_metaphor.explain_mapping(mapping_id, audience, tone)` → Explanation
6. `comic_metaphor.score_codex(mapping_id)` → Dict[str, float]

**Integration**:
- Import from `../../Cheetah-v3-Pro/tools/tool_runs/executor.py`
- Use `ResultCache` for memoization
- Use `ResourceMonitor` for per-phase telemetry
- Return structured `RunResult` objects

**Dependencies**: All engine modules, Cheetah v3 tool_runs framework

## Build Order for Cheetah Marathon

**Phase 1: Data Foundation** (Templates 01, 06, 12)
1. `ingest.py` - Parse existing files
2. `codex_adapter.py` - Wrap existing codex_engine
3. `test_ingest.py` - Validate data ingestion
4. **RUN**: `python -m pytest tests/test_ingest.py`
5. **OUTPUT**: `processed/knowledge_base.json` with 4 protocols

**Phase 2: Retrieval** (Templates 02, 13)
1. `index.py` - Build search index
2. `test_index.py` - Validate search
3. **RUN**: `python -m pytest tests/test_index.py`

**Phase 3: Core Engine** (Templates 03, 14)
1. `metaphor_engine.py` - Mapping logic
2. `test_metaphor_engine.py` - Validate mappings
3. **RUN**: `python -m pytest tests/test_metaphor_engine.py`

**Phase 4: Generation** (Templates 04, 05)
1. `narrative_generator.py` - Outlines and scripts
2. `explainers.py` - Explanations
3. **OUTPUT**: Sample outputs in `output/`

**Phase 5: Cheetah Integration** (Templates 07, 08, 09, 10, 11, 15)
1. `tools_interface.py` - Tool wrappers
2. Scenario files (podcast, marketing, dialogue)
3. `run_benchmark.py` - Benchmark runner
4. `test_integration.py` - End-to-end tests
5. **RUN**: `python benchmarks/run_benchmark.py --all --save-results`
6. **RUN**: `python ../../Cheetah-v3-Pro/run_advisor.py --input benchmark_results/comic_metaphor_*.json`
